   Selected Mood: "Anxious" | Language: "English"
2. Browser issues POST to https://gitaguideai-backend.onrender.com/chat.
3. SlowAPI verifies client IP has not exceeded 5 requests in the rolling minute.
4. Language detection identifies English (skips Step 1 translation).
5. SafetyLayer scans message against self-harm regex patterns (passes safely).
6. Sanitized query is sent via httpx to Hugging Face Inference API.
7. HF returns a 384-float array representing query semantics.
8. NumPy performs dot product against the 701x384 pre-loaded Gita embedding matrix.
9. Top-3 matches emerge: Chapter 2 Verse 47 (Karmanye Vadhikaraste...), Chapter 2
   Verse 48, Chapter 18 Verse 47.
10. Prompt is constructed with retrieved verses, user mood ("Anxious"), and rules.
11. Groq LPU processes LLaMA 3.1 8B and streams back guidance in ~250 milliseconds.
12. Backend returns JSON with generated advice and structured verse metadata.
13. Frontend renders markdown advice and presents interactive shloka cards.

4. ARCHITECTURAL DECISIONS & TRADE-OFF JUSTIFICATIONS
================================================================================

4.1 FastAPI vs. Django / Flask
- Decision: FastAPI 0.115+
- Justification: Native async/await support on ASGI (Uvicorn) allows high
  concurrency during external HTTP calls to Groq and Hugging Face. Pydantic
  guarantees strict request/response data validation. Automatic Swagger UI
  documentation at /docs accelerates integration.
- Trade-off: Flask is synchronous by default; Django brings unnecessary ORM
  and database migration overhead for a static 701-verse dataset.

4.2 Next.js 15 App Router vs. Vanilla React / Vite
- Decision: Next.js 15.1.11 with App Router.
- Justification: First-class edge deployment on Vercel, optimized font delivery,
  hybrid rendering, and zero-configuration asset bundling.
- Trade-off: Stricter build-time validation requiring careful resolution of
  ESLint FlatConfig and hydration boundaries.

4.3 Groq LPU (LLaMA 3.1 8B Instant) vs. OpenAI GPT-4o
- Decision: Groq Cloud API running LLaMA 3.1 8B Instant.
- Justification: Groq's custom Language Processing Units (LPUs) achieve
  generation speeds exceeding 300 tokens/second at near-zero latency (<300ms
  TTFT). It provides rich, empathetic responses with zero billing cost.
- Trade-off: Smaller context window than frontier 128k models, compensated by
  delivering only top-3 concise, high-density verses.

4.4 In-Memory NumPy Vector Search vs. Managed Vector Databases (Pinecone/Milvus)
- Decision: Precomputed NumPy matrix with np.dot cosine similarity.
- Justification: Closed canon of 701 verses. A 701 x 384 float matrix consumes
  only 1.07 MB of RAM. Query calculation executes in ~0.8 milliseconds.
- Trade-off: External vector DBs introduce 50-100ms of network latency, network
  failure points, and monthly subscription bills for zero performance benefit.

4.5 Hugging Face Serverless Inference vs. Local PyTorch Models
- Decision: Hugging Face Inference API (BAAI/bge-small-en-v1.5).
- Justification: Running PyTorch, transformers, and model weights in-process
  consumes >1.2 GB of RAM, immediately triggering Out-of-Memory kills (Exit
  Code 137) on Render's 512 MB free tier. Offloading to HF keeps memory <140 MB.
- Trade-off: Dependent on external API availability; mitigated by generous
  timeouts and connection pooling.

5. RAG PIPELINE MECHANICS & VECTOR MATHEMATICS
================================================================================

5.1 The Vector Math: Why Dot Product Equals Cosine Similarity
The embedding model BAAI/bge-small-en-v1.5 outputs 384-dimensional dense vectors
that are pre-normalized to unit length (L2 norm ||v|| = 1).

General Cosine Similarity Formula:
  CosineSimilarity(A, B) = (A . B) / (||A|| * ||B||)

When vectors are L2-normalized:
  ||A|| = 1.0 and ||B|| = 1.0
  Therefore: CosineSimilarity(A, B) = A . B (Dot Product)

Matrix Dot Product in backend/rag.py:
  scores = np.dot(self.embeddings, query_embedding)
  top_k_indices = np.argsort(scores)[::-1][:limit]

Computational Complexity:
- Matrix multiplication: 701 rows * 384 dimensions = 269,184 floating point ops.
- On standard cloud CPUs, 269k ops execute in ~0.0008 seconds (0.8 milliseconds).

5.2 Cross-Lingual Semantic Gap Resolution
Problem: The vector index is computed over English translations to maximize
semantic retrieval density. When users query in Hindi (e.g., "Mujhe dukh ho raha
hai"), direct vector comparison against English text yields poor similarity.

Solution: Two-Stage Cross-Lingual Pipeline:
1. Language Detection: langdetect detects language code (e.g., "hi").
2. Pre-Retrieval Query Translation: If language != "en", Groq LLaMA 3.1
   translates the emotional query to English in ~100ms.
3. Vector Retrieval: English translation searches the 701-verse index.
4. LLM Synthesis: The LLM receives BOTH original query and retrieved verses:
   user_message = "Original (hi): [Hindi query]\nEnglish: [Translated query]"
5. Output Generation: The LLM generates the final response in fluent Hindi.

6. SAFETY LAYER, GUARDRAILS & CRISIS INTERVENTION PROTOCOLS
================================================================================

6.1 Deterministic Mental Health Crisis Filter
Because spiritual guidance tools attract users in moments of emotional distress,
probabilistic safety moderation is insufficient. GitaGuide AI implements a
deterministic regex safety layer in backend/safety.py that runs BEFORE any RAG
or LLM invocation:

Self-Harm Regex Patterns:
  r"(?i)\b(kill myself|suicide|end my life|want to die|hurt myself)\b"
  r"(?i)\b(cutting myself|overdose)\b"

Short-Circuit Action:
If a match is detected, the pipeline immediately returns:
  "I hear your pain, and I want you to be safe. Please reach out to a
   professional immediately. You can call or text 988 in the US/Canada,
   or contact your local emergency services."
No LLM generation is attempted. No religious rationalization is permitted.

6.2 System Prompt Guardrails
1. Medical / Legal / Financial Disclaimer: Explicit refusal to provide professional
   advice outside philosophical guidance.
2. Anti-Hallucination Rule: Model is forbidden from fabricating Sanskrit verses.
   Verses are provided exclusively through structured database metadata.
3. Separation of Concerns: Advice text is strictly separated from Sanskrit
   shlokas, ensuring clear distinction between philosophy and ancient text.
4. Mood Alignment: Tone dynamically adapts based on user-selected mood (Sad,
   Anxious, Angry, Confused, Seeking Purpose).

8. STAR INTERVIEW CASE STUDIES (REAL-WORLD PROBLEMS SOLVED)
================================================================================

--------------------------------------------------------------------------------
STAR STORY 1: Conquering the 512MB RAM Crash on Render Cloud
--------------------------------------------------------------------------------
- SITUATION: When initially deploying the backend with sentence-transformers
  loading all-MiniLM-L6-v2 in memory, Render containers repeatedly crashed
  during startup with Exit Code 137 (OOMKilled).
- TASK: Reduce backend memory footprint from >1.2 GB to under 512 MB without
  degrading semantic search quality or response latency.
- ACTION: Discovered PyTorch + Hugging Face Transformers consumed 1.2 GB+ of RAM.
  Refactored rag.py to decouple embedding computation from the container.
  Migrated to Hugging Face Serverless Inference API (BAAI/bge-small-en-v1.5)
  and replaced heavy vector databases with an in-memory NumPy dot-product engine.
- RESULT: Memory dropped from 1,200 MB to 135 MB (73% headroom under Render's
  512 MB limit). Container startup time decreased from 45s to 3.2s.

--------------------------------------------------------------------------------
STAR STORY 2: Resolving the Persistent Vercel 404 Routing Anomaly
--------------------------------------------------------------------------------
- SITUATION: Vercel deployment logs reported "Compiled successfully" and "Build
  Completed", yet visiting the live URL produced an immediate 404: NOT_FOUND.
- TASK: Identify why Vercel's edge routing layer was failing to route incoming
  traffic to the compiled Next.js App Router output.
- ACTION: Audited Vercel project settings, discovered an incorrect root directory
  configuration. Then addressed Next.js's static page pre-rendering by adding
  `export const dynamic = 'force-dynamic'` to app/page.tsx, forcing Vercel to
  treat the route as an active serverless function rather than a stale static asset.
  Converted next.config.ts to standard next.config.mjs.
- RESULT: 100% successful route resolution on Vercel's edge network with zero 404s.

--------------------------------------------------------------------------------
STAR STORY 3: React 19 & Next.js 15 ESLint Flat Config & TypeScript Strictness
--------------------------------------------------------------------------------
- SITUATION: Vercel CI/CD failed during build due to ESLint 9 Flat Config crashes
  ("nextVitals is not iterable") and TypeScript compiler errors rejecting
  @ts-nocheck and loose 'any' error types in ChatInterface.tsx.
- TASK: Establish enterprise-grade type safety and achieve zero-warning CI/CD builds.
- ACTION: Updated eslint.config.mjs to use FlatCompat from @eslint/eslintrc,
  bridging Next.js legacy configs into ESLint 9's flat structure. Removed
  @ts-nocheck, implemented strict error type narrowing (err: unknown with
  err instanceof Error), escaped raw JSX quotes, and pruned unused AST parameters.
- RESULT: Clean build completed in 38 seconds. CI/CD pipeline achieved green
  status with zero warnings and strict type safety.

9. TOP 25 TECHNICAL INTERVIEW QUESTIONS & HIGH-IMPACT ANSWERS

--------------------------------------------------------------------------------
Category A: System Design & Architecture
--------------------------------------------------------------------------------

Q1: Walk me through the end-to-end flow when a user sends a message.
A1: The client dispatches an HTTP POST to /chat with message, mood, and language.
    FastAPI applies rate limiting (5 req/min via slowapi). langdetect checks
    query language; if non-English, Groq translates it to English. The SafetyLayer
    scans for self-harm patterns. The cleaned English query is embedded via
    Hugging Face's API into a 384-dim vector. NumPy computes cosine similarity
    against 701 pre-computed Gita verse embeddings. The top-3 verses are assembled
    into context. Groq's LLaMA 3.1 8B generates practical advice adhering to
    formatting guardrails. The JSON payload returns the advice and verse metadata,
    which React 19 renders with Markdown.

Q2: Why separate Frontend on Vercel and Backend on Render instead of a monolith?
A2: Separation of concerns. Next.js excels at edge UI rendering, global CDN
    distribution, and client caching. The Python FastAPI backend is optimized for
    async connection pools, CPU-intensive vector operations, and ML SDKs.
    Decoupling allows either service to scale, restart, or migrate independently
    without downtime on the other.

Q3: How do you handle security and secrets between Vercel and Render?
A3: Strict zero-trust separation. Vercel stores only NEXT_PUBLIC_API_URL (public
    by design). Critical secrets (GROQ_API_KEY, HF_TOKEN) reside exclusively in
    Render's encrypted environment variable store. The browser never communicates
    with Groq or Hugging Face directly.

Q4: How do you handle Render free-tier cold starts?
A4: Render spins down containers after 15 minutes of inactivity. Because our
    FastAPI image does not bundle PyTorch, boot time is ~3 seconds. On the
    frontend, client fetch requests trap timeouts and display a meditative
    loading message. In production, a lightweight scheduled cron ping to /health
    prevents container sleep.

Q5: What rate limiting strategy is implemented?
A5: In-memory token bucket rate limiting via slowapi capping requests at 5 calls
    per minute per client IP. Exceeded limits return HTTP 429, which the UI
    renders as "You are meditating too quickly. Please wait a moment."

--------------------------------------------------------------------------------
Category B: RAG, Embeddings & LLM Engineering
--------------------------------------------------------------------------------

Q6: Why use in-memory NumPy vector search instead of Pinecone or ChromaDB?
A6: Right-sizing architecture. The Bhagavad Gita is a closed canon of 701 verses.
    A 701 x 384 float matrix consumes just 1.07 MB of RAM. np.dot executes in
    ~0.8ms. Introducing Pinecone would add 50-100ms of external network latency,
    recurring monthly costs, and failure points with zero practical upside.

Q7: Why choose BAAI/bge-small-en-v1.5 over OpenAI text-embedding-3-small?
A7: BGE-small-en-v1.5 leads the Massive Text Embedding Benchmark (MTEB) for
    sub-100M parameter models. Its 384-dimensional vectors reduce dot-product
    computation and memory by 75% compared to 1536-dim embeddings, and it is
    free and open-source via Hugging Face.

Q8: How do you prevent LLM hallucinations in spiritual guidance?
A8: 1) Strict RAG grounding: the system prompt forbids citing verses outside
    the retrieved context. 2) Immutable display: verse cards are rendered directly
    from database JSON, not generated text. 3) Scope bounds: the prompt instructs
    the model to acknowledge when a question falls outside Gita teachings.

Q9: What chunking strategy did you use for the Gita?
A9: Natural semantic boundary chunking. Rather than arbitrary character/token
    splits, each chunk corresponds exactly to one canonical verse (Chapter X,
    Verse Y) paired with its commentary, preserving complete spiritual meaning.

Q10: How do you handle cross-lingual vector retrieval?
A10: By translating non-English queries into English via Groq before querying
     the English vector index, aligning the query with the document semantic space.

--------------------------------------------------------------------------------
Category C: Backend & Concurrency
--------------------------------------------------------------------------------

Q11: How does FastAPI's lifespan context manager improve backend efficiency?
A11: It runs setup and teardown logic once at server startup. We initialize a
     shared httpx.AsyncClient with connection pooling and preload the vector
     index, eliminating connection handshake latency on every incoming request.

Q12: Why did you switch from sentence-transformers to Hugging Face Inference API?
A12: PyTorch and transformer weights consumed 1.2 GB of RAM, crashing Render's
     512 MB container. Moving embeddings to the serverless HF API dropped
     memory usage to 135 MB.

Q13: What is the computational complexity of your search operation?
A13: Vector dot product: O(N * D) = 701 * 384 = 269,184 ops. Top-k sorting via
     np.argsort: O(N log k). Total execution time is under 1 millisecond.

Q14: How is CORS configured and secured?
A14: FastAPI's CORSMiddleware dynamically reads authorized domains from
     CORS_ORIGINS. In development, it accepts localhost:3000; in production,
     it is locked to https://gita-guide-ai.vercel.app.

Q15: How are acute mental health risks handled deterministically?
A15: Deterministic regex pattern matching catches self-harm and distress keywords
     prior to LLM processing, immediately returning emergency helpline
     resources (988).

--------------------------------------------------------------------------------
Category D: Frontend & Full-Stack Integration
--------------------------------------------------------------------------------

Q16: Why did Vercel return a 404 despite a successful build?
A16: Next.js was generating static HTML routes while Vercel's edge router looked
     for dynamic serverless functions. Adding `export const dynamic = force-dynamic`
     in page.tsx forced active serverless routing.

Q17: How is Markdown rendered safely without XSS vulnerabilities?
A17: Using react-markdown with remark-gfm. It parses Markdown into an Abstract
     Syntax Tree (AST) and renders safe React elements rather than injecting raw HTML.

Q18: How is theme switching and mood state managed in React?
A18: Component state in ChatInterface.tsx toggles CSS classes on the container.
     The selected mood string is transmitted in the POST request body and
     injected into the LLM system prompt.

Q19: How was the ESLint Flat Config iterable error fixed in Next.js 15?
A19: By installing @eslint/eslintrc and wrapping legacy Next.js configs inside
     FlatCompat, making them compatible with ESLint 9's array-based flat structure.

Q20: Why eliminate @ts-nocheck from production code?
A20: @ts-nocheck disables all compiler checks, allowing silent runtime bugs.
     Removing it and typing catch clauses with err: unknown guarantees
     enterprise-grade type safety.

--------------------------------------------------------------------------------
Category E: Scalability & Future Roadmap
--------------------------------------------------------------------------------

Q21: What would bottleneck first at 1,000,000 queries/day and how would you fix it?
A21: LLM and embedding API rate limits. Solution: Implement Redis semantic
     caching (e.g. GPTCache) to serve repeated questions instantly at 0ms LLM
     latency. Horizontally scale FastAPI across AWS ECS / Cloud Run instances.

Q22: How would you evaluate RAG quality automatically?
A22: Implement the RAG Triad using Ragas or TruLens: 1) Context Relevance,
